## Project Overview

A full-stack Employee Management System built with **React**, **Vite**, **Firebase Authentication**, and **Cloud Firestore**. Administrators can log in, then create, read, update, and delete employee records through a responsive, professional web interface. All database operations are secured by Firestore Security Rules that independently enforce admin-only access.

## Features

- 🔐 **Admin Authentication** — Firebase Email/Password login with Firestore role verification

## Architecture

```
Browser (React + Vite)
        │
        ▼
Firebase Authentication
        │
        ▼ (UID)
Cloud Firestore users/{uid}
        │
        ▼ (role check)
Cloud Firestore employees/*
        │
        ▼
Vercel (Static SPA hosting)
```

All admin operations flow through Firebase directly from the browser. There is no Express/Node backend. Security is enforced by Firestore Security Rules on the Firebase side.

## Firestore Schema

### `users/{uid}`

Stores the role of each authenticated user. This document is read immediately after login to verify admin access.

| Field  | Type   | Description                       |
|--------|--------|-----------------------------------|
| name   | string | Display name                      |
| email  | string | User email address                |
| role   | string | `"admin"` or `"user"`             |

**Example:**
```json
{
  "name": "Admin",
  "email": "admin@example.com",
  "role": "admin"
}
```

### `employees/{employeeId}`

Stores employee records. IDs are auto-generated by Firestore.

| Field       | Type      | Description                        |
|-------------|-----------|-------------------------------------|
| firstName   | string    | Employee first name                 |
| lastName    | string    | Employee last name                  |
| email       | string    | Work email (stored lowercase)       |
| phone       | string    | Phone number                        |
| department  | string    | One of the predefined departments   |
| position    | string    | Job title                           |
| salary      | number    | Annual salary (non-negative)        |
| joiningDate | string    | ISO date string (YYYY-MM-DD)        |
| status      | string    | `"Active"` or `"Inactive"`          |
| createdAt   | Timestamp | Firestore server timestamp          |
| updatedAt   | Timestamp | Firestore server timestamp          |

**Example:**
```json
{
  "firstName": "Priya",
  "lastName": "Sharma",
  "email": "priya.sharma@company.com",
  "phone": "+91 98765 43210",
  "department": "Engineering",
  "position": "Senior Software Engineer",
  "salary": 1200000,
  "joiningDate": "2021-03-15",
  "status": "Active",
  "createdAt": "2026-01-01T00:00:00Z",
  "updatedAt": "2026-01-01T00:00:00Z"
}
```

## Authentication Flow

1. User navigates to `/login`
2. Enters email and password
3. Firebase Authentication verifies credentials
4. On success, the UID is used to read `users/{uid}` from Firestore
5. If `role === "admin"` → redirected to `/dashboard`
6. If `role !== "admin"` or no document exists → signed out immediately, access denied message shown

## Security

### Firestore Security Rules (`firestore.rules`)

The security rules independently enforce all access control. The React UI route guards are for UX only — they cannot be relied upon for security.

**Key behaviors:**

| Actor                          | employees read | employees write |
|--------------------------------|---------------|----------------|
| Unauthenticated user           | ❌ Denied      | ❌ Denied       |
| Authenticated non-admin        | ❌ Denied      | ❌ Denied       |
| Authenticated admin            | ✅ Allowed     | ✅ Allowed      |

**Role escalation prevention:**  
A non-admin user cannot set their own `role` to `"admin"` through a Firestore write. The rules prevent this on the `users` collection.

**No secrets in code:**  
Firebase web config values (API key, project ID, etc.) are loaded from Vite environment variables. They are NOT service-account credentials and cannot be used to bypass Firestore Security Rules.

## Local Setup

### Prerequisites
- Node.js 18+ and npm
- A Firebase project with Authentication and Firestore enabled

### 1. Clone the Repository

```bash
git clone https://github.com/<your-username>/FSD_2_EmployeeManagementSystem_BYTE.git
```

### 2. Install Dependencies

### 3. Configure Environment Variables

Create a `.env` file in the project root:

```env
VITE_FIREBASE_API_KEY=your_api_key
VITE_FIREBASE_AUTH_DOMAIN=your_project.firebaseapp.com
VITE_FIREBASE_PROJECT_ID=your_project_id

VITE_FIREBASE_MESSAGING_SENDER_ID=your_sender_id
VITE_FIREBASE_APP_ID=your_app_id
```

> **Never commit `.env` to Git.** It is listed in `.gitignore`.

### 4. Start the Development Server

```bash
npm run dev
```

Visit [http://localhost:5173](http://localhost:5173).

## Firebase Setup

If setting up from scratch:

1. **Create a Firebase project** at [console.firebase.google.com](https://console.firebase.google.com)
2. **Enable Email/Password Authentication**  
   → Authentication → Sign-in method → Email/Password → Enable
3. **Create a Firestore database** in production mode
4. **Deploy the Firestore rules** (see below)
5. **Create an admin user**:
   - Create the user in Firebase Authentication (Authentication → Users → Add user)
   - In Firestore, create a document at `users/{uid}`:
     ```json
     { "name": "Admin", "email": "admin@example.com", "role": "admin" }
     ```
     Replace `{uid}` with the actual UID shown in the Firebase Authentication console.

### Deploy Firestore Security Rules

Using the Firebase CLI:

```bash
npm install -g firebase-tools
firebase login
firebase init firestore   # select your project
firebase deploy --only firestore:rules
firebase deploy --only firestore:indexes
```

Or paste the contents of `firestore.rules` directly in **Firestore → Rules** in the Firebase Console.

## Deployment (Vercel)

1. Push the repository to GitHub.
2. Import the repository in [vercel.com](https://vercel.com).
3. Vercel auto-detects Vite. Build command: `npm run build`. Output: `dist`.
4. Add all `VITE_FIREBASE_*` environment variables in **Vercel → Project → Settings → Environment Variables**.
5. Deploy. The `vercel.json` rewrites all routes to `index.html`, ensuring SPA routing works on direct navigation and refresh.

> After deployment, verify login, dashboard, CRUD operations, and protected routes on the live URL.
